# 从零还原建筑模型

目标是交付有证据支持、空间逻辑可验证、可维护的产物。把“符合参考资料”“实际几何可通行”“近景展示完整”分开验收。不要先堆细节，再让用户逐处发现结构错误。资料不能支持的部分应明确列为推断或待查，不能承诺仅凭导览图完全还原不可见细节。

## 启动与范围

确认建筑身份、目标时期、格式、用途、展示精度、室内范围及交付位置。用户已确认的选择直接沿用；未指定的重大方向依用户或项目规则确认，阶段检查本身不构成额外审批。用户要完整室内时，范围必须包含全部相关楼层，不能默认只做出发层。

检查可用建模、图像查看、浏览器和导出工具。选择适合当前环境的生成方式，不绑定本机绝对路径、某个建模软件或单一工具。建立单一项目入口和可重建源码。除非用户要求，不为每轮修正创建新版本目录。

## 从零实施的六个阶段

每阶段通过其可检验条件后再投入依赖它的工作。未通过时继续查证或修正，独立部分可以推进；不要用装修替代结构问题的解决，也不要为常规检查反复要求用户确认。

### 1. 收集并消解参考冲突

先执行 [资料检索与结构解释](references/evidence-to-geometry.md)，再按 [参考图到空间台账](references/reconstruction.md) 整理对象。检索以具体未知问题为目标，不能以图片数量为完成标准。实际打开原图，逐图标注观察事实，再跨视角解释；不要从搜索摘要或模糊印象直接跳到生成代码。

**通过条件：**主要立面、屋顶剖面、每个楼层、垂直交通与关键控制区均有来源覆盖。必须产出带证据编号的平面/剖面解释图和关键疑点结论，不能只有下载目录或文字摘要。影响层数、跨层连接、主要外形和受控边界的歧义尚未解决时，不把相关假设固化到精细模型；先补证据，必要时将有依据的备选解释交用户选择。

### 2. 在建模前建立空间和动线合同

以统一坐标、单位和楼层标高记录：建筑轮廓；各层楼板及挑空；每组扶梯/楼梯上下端与方向；每个设施独立的占地多边形；墙、门及门两侧区域；屋面、外部弧梁、内部支撑、檐口和廊道的关系。

读取 [几何与动线验收](references/validation.md)，写出必须连通、禁止连通、必经处理点和先后次序。商店入口先标记公共侧/受控侧，再画门。用少量平面图和剖面叠图检查这些决策，早于装修和家具制作。

**通过条件：**楼层没有遗漏，跨层连接成对对应，主要挑空上下对齐，所有关键开口归属明确，重复设施的不同形状已逐项记录。未确定的尺度可参数化，不能把未确定的空间关系隐藏在代码中。

### 3. 制作低细节模型并验证实际空间

只生成楼板、挑空、外壳、主要柱梁、隔墙、门洞、扶梯包络与设施占地。低细节阶段就导出 GLB，用实际网格检查空间，不能只验证手绘箭头或理想连通图。

**通过条件：**主要外形比例与参考叠图一致；同一空间解释能同时解释内外景和各层图，且能通过未参与拟合的其他视角或锚点核对；所有楼层和设备连通；无整墙堵廊、跨层穿板、悬空栏杆；需要安检/边检的空间不能绕行进入。空间自洽和通路通过不等于符合现实，必须同时完成资料对照。把这一阶段作为减少返工的主要关口。

### 4. 基于已验证边界生成细节

共用一份轮廓数据生成设施墙、玻璃、店顶、入口和测试边界。相似设备可以复用零件，但不能默认复用占地。三角商店必须连店顶和各边都生成三角形，不能用矩形店面叠在原隔板上。

按参考分别制作外部曲梁、内部三角支撑、屋面台阶、檐口端封、门窗、标牌和材质。优先核对影响轮廓的构件，之后才添加小件。标牌检查支撑、文字比例、朝向与安装高度。详细规则见 [参考图到空间台账](references/reconstruction.md)。

**通过条件：**近景、端面、俯视、剖面均与证据相符；新增装修没有侵入已验证通道；牌子和柱梁有正确连接；推断部分在维护记录中可追溯。

### 5. 综合验收与纠错闭环

按 [几何与动线验收](references/validation.md) 检查外观、实际通路、隔离、净空和穿模。用户指出问题时，定位源对象，修正共享轮廓，清除旧实体，并检查相邻对象；不要叠加遮挡补丁。

构建必须成功且输出确实更新，然后才能对新 GLB 验收。失败构建后的旧产物测试无效。每次修改都重做受影响检查；不能通过改掉验收预期来掩盖错误。记录模型哈希、检查范围和对应截图。

**通过条件：**用户已明确提出的每项问题都有证据对应；关键正常路径与禁止绕行测试均通过；截图确实能看清被检查的交接，未完成的重要项如实报告。

### 6. 预览与交付

读取 [预览、证据与交付](references/delivery.md)。整理常用视角、分层显示和必要动线；交互适配建筑尺度。保持主界面简洁，按需归档历史工作，保留源码、参考和检查结果。页面加载的模型与下载模型必须一致。

使用 `python scripts/verify_delivery.py <验收清单.json>` 检查交付文件是否与验收时的哈希一致。脚本只验证证据记录的一致性，不自动证明还原精度或报告真实性，不能靠填写 `pass` 代替实际检查。

最终简要报告完成内容、检查和入口。禁止用“完全还原”“所有穿模已消除”等超出检查证据的结论。仅继续本次高崎项目时，可读 [T3 个案约束](references/t3-case.md)；不将其尺寸、楼层或手续次序套用到所有机场。
