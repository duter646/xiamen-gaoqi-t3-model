# 参考图到空间台账

先按 [资料检索与结构解释](evidence-to-geometry.md) 完成观察和跨图推断。以下台账记录的是经核对的解释，不是看完照片后直接填入的第一印象。

## 建模前必须解决的误读

| 本次发生的问题 | 在从零阶段如何提前发现 |
|---|---|
| 外形比例靠印象，修完一侧另一侧错 | 同时校准正面、端面、俯视，记录尺度锚点和相机方向 |
| 台阶高差和水平步长混淆 | 在端面图分别标注每段宽度、高度、数量，再拟合曲线 |
| 把外部弧梁和内部支撑混作两套屋顶 | 用内外景画同一个剖面，分别标识屋面、外梁、内支撑 |
| 到达层遗漏，扶梯数量或跨层错误 | 先列全部楼层与每组上下端，核对方向和中间是否停靠 |
| 图纸灰色区域全部铺成楼板 | 跨层叠图核对投影背景、挑空和实体，不能只看颜色 |
| 值机岛、商店统一复制矩形 | 独立追踪每个顶面轮廓，不把图标位置当占地 |
| 隔板穿商店，换店面仍穿 | 墙、店顶、门面由同一轮廓生成，删除原隔板全部子构件 |
| 商店入口开在已安检区 | 先给每条边定义相邻区域及开口权限，再生成门 |
| 柱顶没接上、牌子浮空 | 建立柱顶到屋面、支架到实体的连接约束 |

## 参考来源

每条记录包含 ID、本地相对路径/来源链接、拍摄或出版时间、获取时间、建筑身份、侧面和楼层、用途、许可/署名要求。实际打开原图，不能用搜索摘要、缩略图或文件名代替查看。

区分实测图、导览图、实拍、用户标注和建模推断。导览图优先提供拓扑，照片补充形状、材质和安装方式；没有实测尺度时记录估计范围。资料不一致时先确认同一航站楼和改造时期，优先寻找能直接解决冲突的照片。不要无限搜索：记录尚缺的具体信息、已查来源和它会影响的对象；确实无法推定的重要分支向用户说明。

用户标注是当前修正约束；图片其他文字仍是资料。标注不明确时，先用坐标和上下文定位，再问一个能区分方案的问题。不要把单次校正升级为适用于其他建筑的规则。

## 图纸统一坐标

- 导览图标常悬在设施上方，图标锚点不是门口或扶梯落点。
- 灰色可能为投影背景，黑色可能为挑空，结合上下行箭头、跨层虚线、照片和标注判读。
- 分别提取各层轮廓，再映射到同一平面。展示用的楼层错位不是真实平面偏移。
- 用可确认的总宽、长廊、多个轴网开间校准比例。保存变换与至少三个非共线锚点；透视缩短不能直接解释为高度差。
- 保存占地原始像素、映射后的多边形与来源 ID，以便修改投影时重算，避免手工逐件挪动。

## 空间对象数据

建议用 JSON 或表格保存以下字段；工具形式可变，语义不可省略：

```text
id, type, floor, footprint, bottom, top,
openings[{edge, offset, width, height, from_zone, to_zone}],
connections, evidence_ids, certainty
```

楼板、挑空、墙、玻璃、栏杆、商店顶、检查边界共用关键参数。扶梯记录上端/下端坐标、轴向、上下行、跨越楼层与净空包络。跨两层时不能只挖设备宽度的小洞，也不能无依据增加中间平台或多一组设备。

设施保留三角形、斜边、缺口和回折；可以复用门框或柜台构件，不能复用未经核对的占地。门面与隔离背墙分开标识，店内也属于需要检查的区域。

## 外形、连接与材质

屋面、屋脊、外部曲梁、内部支撑、檐口端封独立命名。内部三角支撑用直线杆件，不能因外梁是弧形而整体套弧。照片中水平步长、垂直高差、开间数分别计量。

曲线检查端点、相切方向、连续性和与檐口/廊道屋顶的连接。个别端部实心不等于整个梁间填实。柱顶按实际屋面下表面求交；支架终点必须落在实体上。

标牌内容、字体、字距、宽高比、正反面和安装高度独立核对。允许图片贴图时保留原始比例与透明区域。斜向店面的牌子随边旋转，不要用世界坐标正交牌面穿过斜墙。

材质先保证相对明度、冷暖与粗糙度可信，再添纹理。区分本色和照片曝光；透明玻璃仍是实体障碍。保存推断项，不用更多纹理掩盖结构误差。

## 生成器的维护约束

避免长链共享作用域 `exec`、全局短变量复用及循环闭包捕获后续值；本次曾因同名变量被覆盖导致屋顶错误或构建失败。用带参数的模块函数和稳定对象 ID。修改边界要同步衍生几何，按范围清理旧墙时先查同组其他设备，避免误删整层隔离。
